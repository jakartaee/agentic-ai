== Key Concepts

=== Agent
An agent is a CDI bean that encapsulates autonomous, goal-driven behavior.
Agents are defined using the `@Agent` annotation, which may include an
optional name and description.

=== Workflow
Agent workflows are defined using annotated methods. The workflow is triggered 
by CDI events.

=== Annotations Summary
- `@Agent`: Declares a class as an agent (required on agent class)
- `@Trigger`: Marks a method as a workflow trigger (required - exactly one 
              per agent)
- `@Decision`: Marks a method as a decision point; returns boolean, Result, or
               object (optional - zero or more per agent)
- `@Action`: Marks a method as an action step (optional - zero or more per
             agent)
- `@Outcome`: Marks a method as the workflow outcome (optional - zero or one
              per agent)
- `@HandleException`: Marks a method as an exception handler (optional - zero
                      or more per agent)

=== Large Language Model (LLM) Facade
The `LargeLanguageModel` interface provides a minimal, type-converting facade for LLM
operations. It supports querying with prompts and input objects, returning results as
strings or domain types. Implementations must use Jakarta JSON Binding for
serialization of input objects and deserialization of typed responses.
Implementations may also support unwrapping to access the underlying LLM
implementation for advanced or vendor-specific features.

All `LargeLanguageModel` query methods may throw:

- `IllegalArgumentException` - For null or invalid parameters, or JSON serialization/deserialization failures
- `LLMException` - Runtime exception for LLM service errors (communication failures, invalid responses, rate limiting, timeouts)

=== LLMException
`LLMException` is a runtime exception thrown when LLM operations fail. As a runtime exception,
it does not require explicit handling but can be caught by `@HandleException` methods in agent
workflows. Common failure scenarios include:

- Communication failures with the LLM service
- Invalid or unparseable responses from the LLM
- Rate limiting or quota exceeded errors
- Model unavailability or timeout
- Type conversion failures when processing LLM responses

=== ConstraintViolationException
`ConstraintViolationException` is thrown when Jakarta Validation constraints on method parameters
are violated. As a runtime exception, it does not require explicit handling but can be caught by
`@HandleException` methods in agent workflows. Common scenarios include:

- Method parameter validation failures (`@NotNull`, `@Email`, `@Size`, etc.)
- Custom constraint violations
- Validation of complex domain objects passed between workflow phases

Validation occurs automatically before workflow methods are invoked when parameters
declare Jakarta Validation constraints.

=== Result
The `Result` record standardizes decision outcomes, with a success flag and details object.

=== Terminology

**Agent**:: An autonomous component that responds to events and orchestrates
workflows through flexible combinations of decisions and actions.

**Trigger**:: An event or condition that initiates an agent workflow. Required
for every agent.

**Decision**:: An optional determination point where the agent decides whether
and how to proceed, typically using an LLM. Workflows can have zero, one, or 
multiple decisions.

**Action**:: An optional operation performed by the agent. Workflows can have
zero, one, or multiple actions, and actions can be intermixed with decisions.

**Outcome**:: An optional finalization phase that produces the final result
of the workflow.

**Workflow**:: A flexible execution sequence starting with a trigger, followed 
by any combination of decisions and actions in declaration order, optionally 
ending with an outcome.

**Workflow Context**:: An underlying context object that maintains state
throughout a workflow execution.

**LLM Facade**:: The `LargeLanguageModel` interface that provides access to
Large Language Model capabilities.
