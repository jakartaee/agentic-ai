[[programming-model]]
== Programming Model

This chapter presents the Jakarta Agentic AI programming model: what an
agent is, how a workflow is composed, and how the pieces fit together. The
xref:agent-lifecycle[Annotations and Lifecycle] chapter then defines each
annotation normatively.

=== Agents and Workflows

An agent is a CDI bean annotated with `@Agent` that orchestrates a flexible
workflow. Every workflow begins with a single trigger and may include any
combination of the following phases:

. **Trigger** (required): detects an event or condition that initiates the
  workflow.
. **Decisions** (optional): analyze workflow state and determine whether and
  how to proceed.
. **Actions** (optional): execute operations as part of the workflow.
. **Outcome** (optional): produces or finalizes the result of the workflow.

Decisions and actions can be intermixed in any sequence, allowing agents to
implement simple linear workflows or complex conditional branching.

In addition, an agent may declare `@HandleException` methods to recover from
errors that occur during workflow execution.

==== Workflow Execution (Initial Release)

In the initial release, the runtime orchestrates annotated methods using a
sequential execution model:

. The trigger fires.
. Decisions and actions execute in source-declaration order, intermixed as
  defined.
. Decisions control flow: a `true` or non-`null` return continues; `false`
  or `null` terminates.
. The outcome (if defined) executes once the workflow completes without
  early termination.
. Exception handlers (`@HandleException`) execute if exceptions occur in any
  phase.

The phase rules and per-annotation cardinality are defined normatively in
the xref:agent-lifecycle[Annotations and Lifecycle] chapter.

==== Future Direction

A programmatic workflow API is planned for a subsequent release. It will
wire annotated methods (the basic building blocks) into dynamic, potentially
complex control flows that may be modified at runtime — enabling dynamic
decision routing, conditional action execution, and workflows that adapt
based on agent state or LLM interactions. An initial workflow could be
defined or loaded from storage in a `@PostConstruct` method and persisted in
a `@PreDestroy` method.

=== An Agent at a Glance

The following agent illustrates the model: a CDI bean with a trigger, a
decision that consults an LLM, and an action.

[source,java]
----
@Agent
@ApplicationScoped
public class MonitoringAgent {

    @Inject
    private LargeLanguageModel llm;

    @Inject
    private EventLogger logger;

    @Trigger
    public void onSystemAlert(Alert alert) {
        // Triggered by an external CDI event
    }

    @Decision
    public boolean shouldEscalate(Alert alert) {
        String analysis = llm.query("Should this alert be escalated?", alert);
        return analysis.toLowerCase().contains("yes");
    }

    @Action
    public void escalateAlert(Alert alert) {
        logger.logEscalation(alert);
    }
}
----

=== Jakarta EE Integration

Agents are first-class Jakarta EE citizens. They inject other beans, are
managed by CDI, and participate in transactions, validation, persistence,
messaging, and concurrency just like any other Jakarta EE component.

**Data access**::
- Jakarta Persistence — relational databases
- Jakarta Data — repositories
- Jakarta NoSQL — non-relational databases

**Transactional operations**::
- Jakarta Transactions — `@Transactional` agent methods

**Data serialization**::
- Jakarta JSON Binding — used by `LargeLanguageModel` for structured prompt
  parameters and typed responses

**Messaging and integration**::
- Jakarta Messaging — publish and consume messages (a future trigger
  source)

**Asynchronous operations**::
- Jakarta Concurrency — managed executors for asynchronous work within
  agent logic

[source,java]
----
@Agent
public class DataIntegratedAgent {

    @Inject private EntityManager entityManager;            // Jakarta Persistence
    @Inject private CustomerRepository customerRepo;        // Jakarta Data
    @Inject private Template mongoTemplate;                 // Jakarta NoSQL
    @Inject private ManagedExecutorService executor;        // Jakarta Concurrency

    @Action
    @Transactional                                          // Jakarta Transactions
    public void processCustomerData(CustomerId id) {
        Customer customer = entityManager.find(Customer.class, id);
        List<Order> orders = customerRepo.findOrdersByCustomerId(id);
        mongoTemplate.insert(new AnalyticsEvent(customer, orders));
        executor.submit(() -> generateReport(customer, orders));
    }
}
----

For CDI scoping, observer rules, interceptors, and lifecycle callbacks, see
the xref:cdi-integration[CDI Integration] chapter. For the LLM facade, see
the xref:llm-integration[Large Language Model Integration] chapter.
