== LLM Integration Best Practices

This section provides guidance on effectively using the `LargeLanguageModel` interface.

=== Prompt Engineering

Agents should use clear, specific prompts:

When using the varargs `query(...)` overloads, prefer exact `{}` placeholders
for positional parameters, similar to well-known logger APIs.

A single supplied parameter is also valid when the prompt contains no
placeholder; in that case the parameter remains available as structured
context. Omitting placeholders for multiple supplied parameters is invalid.

[source,java]
----
@Decision
public boolean goodPrompt(Issue issue) {
    // Good: Clear, specific, with expected response format
    String response = llm.query(
        """
        Analyze this issue and respond with YES or NO:
        Title: {}
        Description: {}

        Should this issue be escalated to senior engineers?
        Respond with only: YES or NO
        """,
        issue.getTitle(),
        issue.getDescription()
    );
    return response.trim().equalsIgnoreCase("YES");
}
----

[source,java]
----
@Decision
public String classifyEvent(MyEvent event) {
    return llm.query("Classify this event", event);
}
----

=== Error Handling

You should handle potential LLM failures. The `LargeLanguageModel` interface may 
throw `LLMException` (a runtime exception) for service errors, or 
`IllegalArgumentException` for invalid parameters.

Use try-catch blocks for inline error handling:

[source,java]
----
@Decision
public boolean robustEvaluation(Task task) {
    try {
        String response = llm.query("Evaluate this task", task);
        return parseResponse(response);

    } catch (LLMException e) {
        logger.warn("LLM service error, using fallback", e);
        // Fallback to rule-based decision
        return task.getPriority() == Priority.HIGH;

    } catch (IllegalArgumentException e) {
        logger.error("Invalid parameter to LLM", e);
        return false;
    }
}
----

Or use `@HandleException` methods for workflow-level error handling:

[source,java]
----
@HandleException
public void handleLLMError(LLMException e, Task task) {
    logger.error("LLM failed for task: " + task.getId(), e);
    
    // Mark task for manual review
    task.setStatus(TaskStatus.NEEDS_MANUAL_REVIEW);
    entityManager.merge(task);
    
    // Workflow continues after this method returns
}
----

=== Response Parsing

Parse LLM responses defensively:

[source,java]
----
@Decision
public Priority parsePriority(Issue issue) {
    String response = llm.query(
        "Assess priority (CRITICAL, HIGH, MEDIUM, LOW) for this issue",
        issue
    );

    // Defensive parsing
    String normalized = response.trim().toUpperCase();

    for (Priority p : Priority.values()) {
        if (normalized.contains(p.name())) {
            return p;
        }
    }

    // Default if parsing fails
    logger.warn("Could not parse priority from: " + response);
    return Priority.MEDIUM;
}
----

=== Type-Safe Interactions

Prefer typed responses over string parsing when possible. The
`LargeLanguageModel` facade uses Jakarta JSON Binding to automatically
deserialize LLM responses into Java objects:

[source,java]
----
@Decision
public FraudAnalysis analyzeTransaction(BankTransaction transaction) {
    // Ask LLM to respond with JSON structure
    String prompt = """
        Analyze this transaction for fraud.
        Respond with JSON matching this structure:
        {
          "isFraudulent": true/false,
          "confidence": 0.0-1.0,
          "reason": "explanation",
          "riskLevel": "LOW|MEDIUM|HIGH|CRITICAL"
        }
        """;

    // Automatic deserialization from JSON to FraudAnalysis object
    try {
        FraudAnalysis analysis = llm.query(prompt, FraudAnalysis.class, transaction);
        return analysis;
    } catch (IllegalArgumentException e) {
        // Handle JSON deserialization failures
        logger.warn("Failed to deserialize fraud analysis", e);
        return FraudAnalysis.unknown();
    }
}

// Define a clean Java record for the response
public record FraudAnalysis(
    boolean isFraudulent,
    double confidence,
    String reason,
    RiskLevel riskLevel
) {
    public static FraudAnalysis unknown() {
        return new FraudAnalysis(false, 0.0, "Analysis failed", RiskLevel.UNKNOWN);
    }
}
----

**Benefits of typed responses**:
- Eliminates manual string parsing
- Compile-time type safety
- Clear data structures
- Automatic validation via JSON Binding
- Less error-prone than regex or substring matching

**Best practices**:
- Design response objects that match your LLM's output format
- Include clear JSON structure examples in prompts
- Handle `IllegalArgumentException` for deserialization failures
- Use Java records for immutable response objects
- Provide fallback values when deserialization fails

=== Accessing Vendor-Specific APIs

The `unwrap()` method allows access to vendor-specific implementations, following the same
pattern as Jakarta Persistence's `EntityManager.unwrap()`:

[source,java]
----
@Agent
public class VendorSpecificFeatures {

    @Inject
    private LargeLanguageModel llm;

    @Decision
    public AdvancedResult useVendorFeatures(Data data) {
        // Use portable API when possible
        String basicResult = llm.query("Basic analysis", data);

        // Access vendor-specific features when needed
        try {
            SomeLlmApi vendorApi = llm.unwrap(SomeLlmApi.class);
            return vendorApi.advancedAnalysis(data);
        } catch (IllegalArgumentException e) {
            // Fallback for other implementations
            return parseBasicResult(basicResult);
        }
    }
}
----
