== A Guide to the TCK Distribution

=== Obtaining the Software

The {APILongName} TCK is distributed as a zip file that contains everything needed to run and certify an implementation.
Final releases are published on https://download.eclipse.org/ee4j/agentic-ai/[download.eclipse.org] with a SHA-256 checksum; the certification request asks for that checksum.
The source is in the {APIGitSite}[specification repository].

=== The TCK Environment

Extract the zip. Its layout is:

[source,txt,subs="attributes"]
----
agentic-ai-tck-{TCKVersion}/
  artifacts/
    jakarta.agentic-ai-tck-{TCKVersion}.jar
    jakarta.agentic-ai-tck-{TCKVersion}-sources.jar
    jakarta.agentic-ai-parent-{TCKVersion}.pom
    jakarta.ai.agent.sig_{APIVersion}
    artifact-install.sh
  docs/
    agentic-ai-tck-reference-guide.html
    agentic-ai-tck-reference-guide.pdf
  starter/
  LICENSE
  README.md
----

* `artifacts/` holds the TCK jar and its sources, the parent pom the jar's own pom refers to, a reference copy of the API signature file, and a script that installs the jar and pom into a local Maven repository.
* `docs/` holds this guide.
* `starter/` is a minimal Maven project that runs the TCK once an Arquillian adapter is configured.
* `LICENSE` is the {license}.

=== A Quick Tour of the TCK Artifacts

==== What is included

The TCK jar contains the following packages:

`ee.jakarta.tck.ai.agent`:: The tests, one class per specification section: CDI beans, agent scopes and lifecycle callbacks, event observation, concurrency, parameter resolution, execution order, workflow patterns, workflow termination, `@OnException`, validation constraints, inherited methods, the `LargeLanguageModel` contract, one class per deployment error, and `SignatureTests`, which verifies the API's public structure — every type, member, target, retention and meta-annotation — against the recorded signature file. The agents each class deploys are under `agents`.
`ee.jakarta.tck.ai.agent.framework`:: The test infrastructure: the Arquillian extension that adds the TCK's classes to every deployment, the `TckModel` constants that define the model behaviour required during a run, and the trace recorder.

Every test method's documentation states what it verifies and names the specification section that requires it.
A challenge references a test by its class and method.

==== API signature file

`artifacts/jakarta.ai.agent.sig_{APIVersion}` records the public signature of the `{APIPackage}` package for this release.
It is included for reference; the copy the signature test uses is inside the TCK jar.

==== What is not included

The TCK uses but does not provide a Jakarta EE runtime, an Arquillian adapter or an implementation of {APILongName}.
Setting up a runner project that supplies these is described in <<Creating a TCK Runner>>.
