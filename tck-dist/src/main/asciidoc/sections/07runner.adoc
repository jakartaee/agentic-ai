== Creating a TCK Runner

A small Maven project controls the TCK's lifecycle: it declares the TCK and your Arquillian adapter as dependencies and lets Surefire discover the tests inside the TCK jar.
The `starter/` directory of the distribution is such a project; copy it and complete the two `TODO` items.

=== Installing the TCK artifacts

The runner resolves the TCK as an ordinary Maven dependency.
Install the jar, its sources and the parent pom from `artifacts/` into your local repository:

[source,sh]
----
$ cd artifacts
$ ./artifact-install.sh
----

=== Test Client dependencies

The Test Client needs the TCK, the API, {TCKTestPlatform}, the Arquillian {TCKTestPlatform} integration and an Arquillian adapter for your runtime.

[source,xml]
----
include::{starterLoc}/pom.xml[tag=testClientDep]
----

The adapter is specific to your runtime and is the one item the starter cannot supply.
A managed or remote adapter runs the Test Server as a separate process; an embedded adapter runs it in the Test Client JVM, in which case the implementation and everything it needs must be on the Test Client class path.

=== Configuring {TCKTestPlatform}

The tests live in the TCK jar rather than in the runner, so Surefire must be told to scan that dependency:

[source,xml]
----
include::{starterLoc}/pom.xml[tag=configJunit5]
----

Surefire's default include patterns match the TCK's test classes, which are named `*Tests` and `*Test`.
No `groups` or `excludedGroups` configuration is needed or permitted: a compatibility run executes every test.

=== Configuring Arquillian

Arquillian reads `src/test/resources/arquillian.xml` for the adapter's connection settings, such as host, port and credentials.
The property names are defined by the adapter.
The starter ships a commented template.

Deployment archives are complete as the TCK builds them.
If your runtime needs an additional deployment descriptor in every archive, add it with your own Arquillian `ApplicationArchiveProcessor`, registered through `META-INF/services/org.jboss.arquillian.core.spi.LoadableExtension` in the runner project.
