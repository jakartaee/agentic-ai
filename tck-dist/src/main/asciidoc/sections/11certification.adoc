== Certification of Compatibility

The {TCKProcessDoc}[Jakarta EE TCK Process] defines how compatibility with {APILongName} is certified through execution of this TCK.

From the *Jakarta EE TCK Process*:

> Jakarta EE is a self-certification ecosystem.
> If you wish to have your implementation listed on the official https://jakarta.ee implementations page for the given specification, a certification request as defined in this section is required.

=== Filing a Certification Request

Certification requests are tracked as issues labeled `certification` in the {ExistingCertifications}[specification repository].
File one with the {RequestCertification}[Compatibility Certification Request issue template].
It asks for the organization, the product and its version, the specification and TCK versions, the SHA-256 checksum of the TCK distribution zip, a public link to the results summary, the Java runtime and environment used, acceptance of the {licenseURL}[{license}] and an attestation that all TCK requirements, including the rules in <<Rules for {APILongName} Products>>, have been met.

=== Additional Certification Requirements

The TCK verifies the implementation's own `LargeLanguageModel` facade.
A real model cannot give deterministic answers, so for the duration of the TCK run the implementation must back its facade with a model that behaves as follows.
The constants are in `ee.jakarta.tck.ai.agent.framework.TckModel`, and "rendered prompt" means the text the facade sends to the model after substituting each `{}` placeholder with the Jakarta JSON Binding serialization of the corresponding parameter (a prompt without placeholders is sent unchanged, whether or not a structured-context parameter accompanies it).

. If the rendered prompt contains `TckModel.FAIL` (`[tck:fail]`), the model fails. The facade must surface that failure as `LLMException`.
. If the rendered prompt is exactly `TckModel.HISTORY` (`[tck:history]`), the model returns the rendered prompts previously sent in the current conversation — the current workflow context — in order, one per line, joined with `\n`; the empty string if there are none. History requests are not themselves recorded.
. Otherwise the model returns the rendered prompt, verbatim. Typed `query` overloads therefore deserialize that echoed text with JSON Binding.

How the implementation selects this model for the run is its own concern; a test configuration or profile of the implementation is the expected means.
The facade logic the TCK asserts — placeholder handling, serialization, deserialization, exception mapping, per-workflow conversational state and thread safety — must be the implementation's production code; only the model transport is substituted.
State in the certification request how the requirement was met.
