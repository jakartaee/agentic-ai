== Signature Test

The signature test validates the integrity of the `{APIPackage}` package as the Test Server provides it to applications.
It catches an incomplete or modified copy of the API in a runtime that ships its own, and non-specified additions to `{APIPackage}` in any.

=== How it runs

`ee.jakarta.tck.ai.agent.framework.signature.SignatureTests` is a test class in the TCK jar like every other: it declares an Arquillian deployment and runs inside the Test Server, in the same {TCKTestPlatform} execution, with no plugin configuration:

. Its deployment carries the signature file `jakarta.ai.agent.sig_{APIVersion}` and the Jakarta TCK signature test engine, both taken from the Test Client class path.
. Inside the Test Server it locates the jar or directory that supplies `{APIPackage}.Agent`, plus the one that supplies the CDI types the API refers to.
. It runs the engine in strict static mode over those locations, resolving JDK types at the Java SE {JavaVersion} level.

The check is strict in both directions: a missing, changed or added public or protected member fails it.
Because the JDK view is pinned to Java SE {JavaVersion}, the result is the same on any JDK of that version or later, and no `jimage` extraction, module exports or additional JVM options are needed.

=== Which API is tested

Whatever supplies `{APIPackage}` to applications deployed on the Test Server is tested: the API jar your runtime ships, or your implementation jar if it bundles the API.
With a managed or remote adapter this is independent of the `jakarta.agentic-ai:jakarta.agentic-ai-api` dependency the starter declares, which only compiles and loads the test classes on the Test Client.

=== Expected output

A passing run reports the class like any other:

[source,txt]
----
Tests run: 1, Failures: 0, Errors: 0, Skipped: 0 -- in ee.jakarta.tck.ai.agent.framework.signature.SignatureTests
----

A failing run includes the engine's report in the assertion message, listing the members that differ from the signature file under headings such as `Missing Methods` or `Added Methods`.
